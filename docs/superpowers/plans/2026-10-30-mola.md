# Mola Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a private Windows desktop voice/chat/screensharing application for ten friends with automatic coordinator failover.
**Architecture:** Each desktop holds an authenticated peer service and SQLite event log. Group-CA mutual TLS authenticates members; signed immutable events converge over peer connections. WebRTC media remains independent of coordinator selection.
**Tech Stack:** TypeScript, Electron, React, esbuild, Node TLS/crypto, node-forge, ws, sql.js, node:test via tsx.
**Spec:** ../../../../../outputs/2026-10-30-ozel-sohbet-tasarimi.md (approved in chat).

## Global Constraints
- Windows 10/11 x64; no publishing, no paid services, no installing VPN or modifying firewall automatically.
- Maximum ten members, one broadcast per connected component, voice to nine peers.
- Bind only selected private interface, never all interfaces. Normal TLS certificate validation stays enabled.
- Persistent replicated messages; no false remote backup acknowledgement. No perpetual uptime if all apps are closed.
- Microphone and screen capture require user action. Context isolation and sandbox enabled; no remote scripts.
- Real two-network hardware verification remains a required external acceptance check, never claimed by local tests.

## Review Focus
- Offline revocation must converge using signed sequence cutoffs (Task 1).
- Restarted or partitioned peers must not overwrite history or misreport durability (Tasks 1, 2).
- Untrusted invites, frames and IPC must be bounded and fail closed (Tasks 1–3).
- Media permission denial, track end and simultaneous offers must release resources and recover (Task 4).
- No-adapter first launch and packaged asset lookup must provide a usable path (Tasks 3, 5).
